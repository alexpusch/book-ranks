# App overview

## Purpose

Book ranks is a local book tier list generator. Users enter books, choose Open Library covers, rank them in customizable tiers, and export their rankings as a JPEG.

## How it works

- **App icon:** A book-and-tiers icon identifies the app in browser tabs and supported home-screen bookmarks.
- **Book entry:** Add one book at a time using a compact input. Manual entry is the first tab. AI assisted is offered when the Prompt API reports an available, downloadable, or downloading model, but is selected by default only when the model is already available; otherwise manual entry is the default. AI assisted help highlights the initial Gemini Nano download warning in yellow with a warning icon only while the model is not yet downloaded; it disappears after download completion. Manual entry remains usable during the check, and a manual selection or draft is not interrupted when the check completes. Check failures show an explicit error. AI assisted submissions immediately enter the gallery as placeholder cards showing the exact submitted text and a spinning Chrome icon, without textual AI progress. The input clears immediately and stays available for more submissions. A FIFO queue extracts names with the on-device Prompt API, then looks up covers; normalization updates the same card and preserves ranking and explicit artwork. Failures, multiple-book results, and normalized duplicates keep the original card with an error and retry/edit actions; one failure does not block later entries. Pending input is saved and resumes on reload; deleted or manually edited entries ignore late results. Manual entry provides book-name and optional-author fields and does not require AI to add a book. Missing authors remain unknown. Duplicate matching ignores case and extra whitespace. Switching modes or collapsing the panel preserves each mode's draft; there is no automatic parser or cloud fallback.
- **Entry layout:** Add books and the gallery form one visual panel, with the gallery at the bottom. A progress bar below the entry fields shows Chrome's initial model download, including downloads already in progress, and disappears on initialization completion, failure, or cancellation. Availability checks, cached-model initialization, and inference do not show it. Mode tabs are hidden while checking Prompt API support or when it is unavailable; users see the manual form directly. The collapsible title sits above the full-width entry form in both modes and at all screen sizes; collapsing hides only the form. When scrolling, the title and form scroll away and only the gallery remains sticky.
- **Ranking:** New books appear in a single horizontally scrolling gallery with no heading or subtitle; the empty gallery shows "your books". A cartoonish curved arrow labeled "drag to rank" floats outside the gallery's left edge without taking book space; it is hidden below 1420px viewport width where the page margin cannot fit it. The reading pile sticks to the top of the viewport when scrolling through lower tiers, on desktop and mobile, with a subtle shadow only while pinned. Drag whole cards into tiers, between tiers, within a tier, or back to the gallery. Mouse, keyboard, and touch dragging are supported; cards have no drag icon, tier menu, or ordering buttons. Removing a ranked book returns it to the end of the unranked gallery with its details and cover intact; removing it from the gallery deletes it from the list.
- **Drop feedback:** Tiers and the gallery stay highlighted while dragging over either their empty space or their book cards, including when reordering. The highlight clears when leaving the zone, dropping, or canceling.
- **Tier settings:** Start with S, A, B, C, D, and E. Users can add, rename, recolor, reorder, or delete tiers. At least one tier remains; deleting a tier returns its books to the gallery.
- **Theme:** An icon-only sliding switch beside Tier settings offers gray/black dark mode with muted gold buttons and accents, or light mode. The switch uses moon/sun icons, a tooltip, and an accessible label instead of visible text. It switches the page, forms, and dialogs for the current session, starting in light mode. JPEG exports use the theme selected when export starts; tier colors and cover artwork are unchanged.
- **Saving:** Automatically save a versioned board snapshot in browser localStorage. Validate restored data and show storage errors or explicit recovery options rather than silently replacing invalid data.
- **Lookup:** After import, cards show waiting/active indications while books are resolved one at a time. Fetch up to 10 Open Library search results directly from the browser, omitting the author filter when unknown and excluding legacy edition records from work candidates; Chrome AI selects a supplied work ID by title and any provided author or declines to match. Without the Prompt API or when it reports unavailable, always choose a search candidate without exact title/author restrictions: inspect the first page of up to 20 editions per candidate with artwork and prefer the newest dated edition with a cover. Fall back to the first result with artwork, or the first result if none have artwork; ties preserve search/edition order. Actual API/model and edition-request failures remain explicit errors. Apply the selected result's actual title/authors and selected edition or representative cover, never model-generated metadata. Preserve placements and explicit selections; ignore late results after edits/deletion. Metadata collisions require review rather than merging duplicate books. Persist matched work IDs even without artwork so reload does not repeat completed matches.
- **Custom covers:** The editor gallery offers Upload photo and Paste image (then Ctrl+V or Command+V). Images are decoded and resized locally, saved with the board, and included in JPEG exports; no image upload requests occur.
- **Covers:** Only non-AI initial lookup automatically fetches one edition page per search candidate with artwork; AI lookup and opening the editor do not fetch editions. The editor's explicit additional-editions button loads up to 20 editions for the matched work; subsequent pages require another click. The accessible gallery deduplicates cover IDs and shows available release dates. Choosing artwork does not replace book metadata, and users can explicitly keep a placeholder. Persist identifiers/choices, including selected edition IDs, not URLs or transient request state, in additive version-1 snapshots; existing saved choices remain compatible. Artwork loads directly from Open Library with fallback and explicit retry on image failures.
- **Export:** A floating button at the bottom right downloads the full tier board, including empty tiers, as a JPEG at 1x resolution (normally 1100px wide), with narrow 8px outer padding and the current URL (without its query string) at the bottom left. No title or app branding is included. Exclude unranked books and controls, and render separately so offscreen rows and long labels are included. Snapshot current selections, use placeholders for unresolved covers without an informational warning, preflight and reuse verified image bytes with timeouts, and require an explicit placeholder decision for failed selected artwork.

## Implementation

- **Frontend:** Client-only React SPA with Vite and TypeScript, deployable to HTTPS static hosting. No application backend, database, server configuration, or private credentials. `@dnd-kit` handles dragging; `html-to-image` generates JPEGs in the browser.
- **Deployment:** [GitHub Actions](./.github/workflows/deploy-pages.yml) builds and deploys to GitHub Pages on pushes to `main` or manual runs, using the configured Pages base path.
- **State:** [src/board/](./src/board/) defines books, tiers, ordered placements, persisted cover selections, immutable board operations, and snapshot validation/persistence. [src/app/useBoard.ts](./src/app/useBoard.ts) owns React board state, autosave, and storage recovery.
- **UI:** [src/app/App.tsx](./src/app/App.tsx) composes the app. [src/books/](./src/books/) owns entry forms, editing, book/artwork rendering, and local image preparation. [src/ranking/](./src/ranking/) owns drag interactions, gallery/tier layout, and tier settings. [src/export/](./src/export/) owns separate export rendering and JPEG generation.
- **Book resolution:** [src/bookResolution/](./src/bookResolution/) owns extraction, matching, per-book lookup status, FIFO processing, cancellation, stale-result protection, metadata updates, and explicit edition discovery, independently of UI rendering. [src/integrations/chromeAi/prompt.ts](./src/integrations/chromeAi/prompt.ts) owns shared prompt serialization, model progress, and session cleanup.
- **Open Library:** [src/integrations/openLibrary/client.ts](./src/integrations/openLibrary/client.ts) owns direct metadata requests, bounded response validation, pagination, cancellation, timeouts, and retries. Searches, edition pages, and retries share one per-tab queue with at most one request in flight and at least one second between starts. Respect throttling/backoff and surface failures explicitly. No persistent metadata/image cache or cross-tab/global rate enforcement. Pasted text and candidates stay on-device for AI; Open Library receives search terms.
- **Verification:** Vitest and React Testing Library cover model/UI behavior; Playwright covers static hosting, browser interactions, responsive layout, persistence, and JPEG downloads using mocked Open Library and Chrome AI. A separate opt-in Playwright evaluation runs a varied extraction dataset against real Chrome AI in headless Chrome, reusing a persistent model profile and comparing search-ready title/author pairs without catalog requests.

Accounts, multiple saved lists, sharing, server-side uploads, and bulk crawling are out of scope. Offline Open Library artwork and cover-art redistribution rights are not guaranteed. See [README.md](./README.md) for setup, network requirements, commands, and detailed usage.
