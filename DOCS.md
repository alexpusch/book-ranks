# App overview

## Purpose

Book ranks is a local book tier list generator. Users enter books, choose Open Library covers, rank them in customizable tiers, and export their rankings as a JPEG.

## How it works

- **Hidden AI mode:** AI-assisted book entry is included only when the URL contains `ai=true`. Other URLs offer manual entry and bulk insert, skip the entry availability check, and preserve any saved AI entry preference without applying it. Existing queued books and cover lookup behavior are unchanged.
- **Bulk insert:** Always available alongside manual entry, without Chrome AI or a URL flag. A single textarea accepts one book per line in `book title | author(s) name` format. The shared import parser trims whitespace, ignores blank lines, allows omitted authors, and preserves duplicates as separate books. Invalid lines show line-numbered errors and reject the entire batch without clearing the draft. Successful submission adds all books to the gallery in input order, clears only the bulk draft, and starts the existing cover-lookup flow. Bulk mode has its own draft across mode changes; its explicit selection is saved.
- **App icon:** A book-and-tiers icon identifies the app in browser tabs and supported home-screen bookmarks.
- **Search discovery:** Static page titles and descriptions, canonical and social metadata, WebApplication structured data, and a single-page sitemap identify the public GitHub Pages URL without adding visible SEO copy to the app. Saved boards remain local and are not published or indexed.
- **Book entry:** Manual entry adds one book using compact inputs; AI assisted and bulk insert use multiline textareas and add batches. AI accepts long book lists and copied library pages, including Audible. It extracts every library entry in order, ignoring narrators, controls, descriptions, and repeated headings within an entry. Long pastes are split at paragraph boundaries (or lines for oversized paragraphs) into smaller on-device prompts; no partial batch is added if any prompt fails. Manual entry is the first tab. AI assisted is offered when the Prompt API reports an available, downloadable, or downloading model, but is selected by default only when the model is already available; otherwise manual entry is the default. AI assisted help highlights the initial Gemini Nano download warning in yellow with a warning icon only while the model is not yet downloaded; it disappears after download completion. Manual and bulk entry remain usable during the check and extraction, and their selection or drafts are not interrupted. Check failures show an explicit error. AI submission leaves the text in the form and disables only the AI textarea and submit button, showing a spinning loader on **+ Add books** until every extraction chunk completes. No raw-text card is inserted. Successful extraction adds all books to the latest board atomically, then starts the FIFO cover-lookup queue and clears the AI draft. Failures show a form error and retain the text for editing or retrying with the same button. Unmounting or resetting saved data cancels form extraction; unfinished submissions are not saved as cards. Previously saved pending cards still resume through the legacy resolution queue, preserving ranking and artwork and ignoring late results after deletion or edits. Manual entry provides book-name and optional-author fields and does not require AI to add a book. Missing authors remain unknown. Duplicate books are allowed in entry, editing, AI normalization, lookup, and saved boards; each copy keeps independent ranking and artwork. Switching modes preserves each mode's draft; AI entry has no automatic parser or cloud fallback.
- **Entry layout:** Add books and the gallery form one visual panel, with the gallery at the bottom. A progress bar below the entry fields shows Chrome's initial model download, including downloads already in progress, and disappears on initialization completion, failure, or cancellation. Availability checks, cached-model initialization, and inference do not show it. Manual entry and bulk insert tabs are always available; the AI tab appears only after the opted-in Prompt API check reports support. The non-interactive title sits above the always-visible, full-width entry form in all modes and at all screen sizes. When scrolling, the title and form scroll away and only the gallery remains sticky.
- **Clear gallery:** A small red X "Clear all" button directly above the unranked gallery matches the ranking clear button's styling and deletes all unranked books, preserving ranked books, covers, tier settings, and entry drafts. It scrolls away while the gallery stays sticky, is disabled when the gallery is empty, and the cleared board is saved automatically.
- **Ranking:** New books appear in a single horizontally scrolling gallery with no heading or subtitle; the empty gallery shows "your books". A cartoonish curved arrow labeled "drag to rank" floats outside the gallery's left edge without taking book space; it is hidden below 1420px viewport width where the page margin cannot fit it. The reading pile sticks to the top of the viewport when scrolling through lower tiers, on desktop and mobile, with a subtle shadow only while pinned. Drag whole cards into tiers, between tiers, within a tier, or back to the gallery. Mouse, keyboard, and touch dragging are supported; cards have no drag icon, tier menu, or ordering buttons. Removing a ranked book returns it to the end of the unranked gallery with its details and cover intact; removing it from the gallery deletes it from the list.
- **Clear rankings:** The red X "Clear all" button beside the ranked count returns every tier's books to the end of the gallery in tier and book order, preserving book details, covers, and tier settings. It is disabled when no books are ranked, and the cleared board is saved automatically.
- **Gallery scrolling:** Adding books in any mode horizontally scrolls the gallery to reveal the last newly added book without moving the page vertically. Restoring a board, editing books, reordering, or returning ranked books to the gallery does not trigger this automatic scroll.
- **Drop feedback:** Tiers and the gallery stay highlighted while dragging over either their empty space or their book cards, including when reordering. The highlight clears when leaving the zone, dropping, or canceling.
- **Tier settings:** Start with S, A, B, C, D, and E. Users can add, rename, recolor, reorder, or delete tiers. At least one tier remains; deleting a tier returns its books to the gallery.
- **Theme:** An icon-only sliding switch beside Tier settings offers gray/black dark mode with muted gold buttons and accents, or light mode. The switch uses moon/sun icons, a tooltip, and an accessible label instead of visible text. It switches the page, forms, and dialogs, restoring the saved choice on reload and starting in light mode when no choice is saved. JPEG exports use the theme selected when export starts; tier colors and cover artwork are unchanged.
- **Preferences:** Explicit book-entry mode and theme choices are saved separately from the board in browser localStorage. A saved entry mode overrides the availability-based default; when Chrome AI is unavailable, manual entry remains usable without overwriting the saved choice. Preference storage failures show warnings and do not block the controls.
- **Saving:** Automatically save a versioned board snapshot in browser localStorage. Validate restored data and show storage errors or explicit recovery options rather than silently replacing invalid data.
- **Lookup:** After import, cards show waiting/active indications while books are resolved one at a time. Fetch up to 10 Open Library search results directly from the browser, omitting the author filter when unknown and excluding legacy edition records from work candidates. Manual entry and bulk insert automatically select the first work whose title and full comma-separated author names match the supplied fields case-insensitively, normalizing whitespace. Exact matches use representative artwork without AI or edition requests, and persist even without artwork. Missing authors do not qualify. Multiple results without an exact match require user review; otherwise Chrome AI selects a supplied work ID by title and any provided author or declines to match. Without the Prompt API or when it reports unavailable, choose a search candidate without exact title/author restrictions: inspect the first page of up to 20 editions per candidate with artwork and prefer the newest dated edition with a cover. Fall back to the first result with artwork, or the first result if none have artwork; ties preserve search/edition order. Actual API/model and edition-request failures remain explicit errors. Apply the selected result's actual title/authors and selected edition or representative cover, never model-generated metadata. Preserve placements and explicit selections; ignore late results after edits/deletion. Matching metadata never merges books. Persist matched work IDs even without artwork so reload does not repeat completed matches.
- **Book editing:** Save applies title and author edits; the editor has no cover-search retry button. When lookup finds no match, it shows "No matching works found" without an edition-search button or matching instructions. Matched books retain explicit edition discovery. Cards needing artwork show the normal placeholder without a "Review required" label; the separate "Multiple matches" review flow is unchanged.
- **Manual match review:** When a manual-entry or bulk-insert search returns multiple works without an exact title-and-author match, keep the entered details and replace the card's book graphic with a dedicated theme-aware background, a large question mark, and centered "Multiple matches" text beneath it. These cards offer only review (magnifying glass) and removal, with no drag area until resolved. Review opens a right-side panel with candidate titles, authors, and search-result covers (or placeholders). It starts with the first search page (up to 10 results); Show more appends another page per click, deduplicates work IDs, and disappears when no pages remain. Failed pages leave earlier matches available and can be retried. Title/author fields and Search query Open Library directly without AI or edition discovery, resetting pagination; unsent field edits do not change Show more's query. Selecting a work saves its actual metadata, work ID, and representative cover, preserves placement and explicit artwork, and closes the panel; works without covers remain selectable. Search errors and empty results are explicit, and closing or replacing a search cancels it.
- **Custom covers:** The editor gallery offers Upload photo and Paste image, which reads and applies a clipboard image immediately without an extra form or keyboard paste. The browser may request clipboard permission; unsupported clipboard access, denied permission, and missing images show errors with an upload alternative. On the main screen, hovering a gallery or ranked book card and pressing Ctrl+V (Command+V on Mac) applies a clipboard image directly, without opening the editor. The card tooltip says "cmd+v to paste cover image" on Mac and "ctrl+v to paste cover image" on Windows and Linux; there is no paste icon. Text-field paste, open dialogs, and dragging are unaffected. Images are decoded and resized locally, saved with the board, and included in JPEG exports; no image upload requests occur.
- **Covers:** Non-AI initial lookup without an exact match automatically fetches one edition page per search candidate with artwork when no multiple-match review is needed; exact matches, AI lookup, and opening the editor do not fetch editions. The editor's explicit additional-editions button loads up to 20 editions for the matched work; subsequent pages require another click. The accessible gallery deduplicates cover IDs and shows available release dates. Choosing artwork does not replace book metadata, and users can explicitly keep a placeholder. Persist identifiers/choices, including selected edition IDs, not URLs or transient request state, in additive version-1 snapshots; existing saved choices remain compatible. Artwork loads directly from Open Library with fallback and explicit retry on image failures.
- **Export:** A floating button at the bottom right downloads the full tier board, including empty tiers, as a JPEG at 1x resolution (normally 1400px wide), with narrow 8px outer padding and the current URL (without its query string) at the bottom left. No title or app branding is included. Exclude unranked books and controls, and render separately so offscreen rows and long labels are included. Snapshot current selections, use placeholders for unresolved covers without an informational warning, preflight and reuse verified image bytes with timeouts, and require an explicit placeholder decision for failed selected artwork.

## Implementation

- **Frontend:** Client-only React SPA with Vite and TypeScript, deployable to HTTPS static hosting. No application backend, database, server configuration, or private credentials. `@dnd-kit` handles dragging; `html-to-image` generates JPEGs in the browser.
- **Deployment:** [GitHub Actions](./.github/workflows/deploy-pages.yml) builds and deploys to GitHub Pages on pushes to `main` or manual runs, using the configured Pages base path.
- **State:** [src/board/](./src/board/) defines books, tiers, ordered placements, persisted cover selections, immutable board operations, and snapshot validation/persistence. [src/app/useBoard.ts](./src/app/useBoard.ts) owns React board state, autosave, and storage recovery.
- **UI:** [src/app/App.tsx](./src/app/App.tsx) composes the app. [src/books/](./src/books/) owns entry forms, editing, book/artwork rendering, and local image preparation. [src/ranking/](./src/ranking/) owns drag interactions, gallery/tier layout, and tier settings. [src/export/](./src/export/) owns separate export rendering and JPEG generation.
- **Book resolution:** [src/bookResolution/](./src/bookResolution/) owns extraction, matching, per-book lookup status, FIFO processing, cancellation, stale-result protection, metadata updates, and explicit edition discovery, independently of UI rendering. Extraction conservatively collapses matching duplicate Audible headings to their supplied short title and full author line before inference, then processes text in chunks of at most 6,000 characters. Audible output is constrained and validated against the number of `By:` entries; missing or extra books reject the batch with an explicit retryable error. Other text keeps the existing general extraction instructions. [src/integrations/chromeAi/prompt.ts](./src/integrations/chromeAi/prompt.ts) owns shared prompt serialization, model progress, and session cleanup.
- **Open Library:** [src/integrations/openLibrary/client.ts](./src/integrations/openLibrary/client.ts) owns direct metadata requests, bounded response validation, pagination, cancellation, timeouts, and retries. Searches, edition pages, and retries share one per-tab queue with at most one request in flight and at least one second between starts. Respect throttling/backoff and surface failures explicitly. No persistent metadata/image cache or cross-tab/global rate enforcement. Pasted text and candidates stay on-device for AI; Open Library receives search terms.
- **Verification:** Vitest and React Testing Library cover model/UI behavior; Playwright covers static hosting, browser interactions, responsive layout, persistence, and JPEG downloads using mocked Open Library and Chrome AI. A separate opt-in Playwright evaluation runs a varied extraction dataset against real Chrome AI in headless Chrome, reusing a persistent model profile and comparing search-ready title/author pairs without catalog requests.

Accounts, multiple saved lists, sharing, server-side uploads, and bulk crawling are out of scope. Offline Open Library artwork and cover-art redistribution rights are not guaranteed. See [README.md](./README.md) for setup, network requirements, commands, and detailed usage.
